# Persistence Schema — V0.1.5

**Date**: September 2026 (code state `72c2b41`, release `v0.1.5`)
**Version field**: `"version": 3` in every persistence file — **unchanged by this release**
**Purpose**: Document the one new persisted location introduced with customizable print templates.
**Releases**: V0.1.5

---

## Overview

V0.1.5 makes the layout of the printed documents customizable, which adds a directory of files that the application writes and reads back. It does **not** touch the turn, register, inventory or configuration files: their schema stays at `version: 3`, no migration is added, and a data directory created by V0.1.4.1 is used as it is.

- **New directory**: `data/printTemplates/`, holding at most four optional JSON files.
- **Write path**: the template editor (Options → Printer configuration → CONFIGURAR IMPRESION), atomic `.tmp` + move like the rest of the file I/O.
- **Read path**: `Printer`, when printing; and the editor, when opening a type.
- **Absence is a valid state**: with the directory empty or missing, printing uses the built-in layout in `Printer`.
- **Not turn data**: these files never feed back into the turn, the register, the history or the reports.

## 1. `data/printTemplates/<type>.json`

| File | Document | Since |
|------|----------|-------|
| `room_receipt.json` | Recibo de habitación | V0.1.5 |
| `sale_receipt.json` | Recibo de venta | V0.1.5 |
| `turn_summary.json` | Resumen de turno | V0.1.5 |
| `turn_detail.json` | Detalle de turno | V0.1.5 |

Each file is a `templateType` plus a list of bands → lines → segments; the format, the available field keys per document and the style names are documented in [Print Templates](../PRINT_TEMPLATES.md). The `templateType` of a file must match the type its file name encodes.

### Resolution order when printing

| Step | Source | Used when |
|------|--------|-----------|
| 1 | `data/printTemplates/<type>.json` | The file exists and parses |
| 2 | Built-in layout in `Printer` (Java code) | In every other case: no file, unreadable file, or a render failure |

The factory defaults shipped inside the `.jar` (`/printTemplates/<type>.json`) are the editor's starting point for a type that has not been customized; `Printer` never reads them directly, because step 2 already covers that case.

### Writes

| Action | Effect on disk |
|--------|----------------|
| `GUARDAR` in the editor | Creates or replaces `data/printTemplates/<type>.json` |
| `BORRAR PLANTILLA` in the editor | Deletes the file, returning the type to the built-in layout |
| `RESTAURAR POR DEFECTO` | Editor state only; nothing is written until `GUARDAR` |
| `IMPRIMIR PRUEBA` | Nothing is written |

Deleting the whole directory is equivalent to never having customized a template.

## 2. Unchanged files

The four active state files and the completed-turn archives keep the V0.1.4.1 schema exactly: `"version": 3`, `ZonedDateTime` in `America/Bogota`, amounts as `long` in COP, `RoomData` records embedded in turn activities. See [V0.1.4.1](V0.1.4.1.md) for the full description.
