# Persistence Schema — V0.1.5.3

**Date**: September 2026 (code state `0b9521e`, release `v0.1.5.3`)
**Version field**: `"version": 3` in every persistence file — **unchanged by this release**
**Purpose**: Document the `keypadEnabled` setting of the on-screen keypad.
**Releases**: V0.1.5.3

---

## Overview

V0.1.5.3 adds one optional key at the top level of `data/applicationProperties`, next to the
motel identity, the printer name and the currency configuration. No file, no directory and no
migration step is added, and a directory written by any version since V0.1.4.1 is read as it is.

| File | Change | Compatibility |
|------|--------|---------------|
| `data/applicationProperties` | optional `keypadEnabled` | Absent in older files → the keypad is **enabled** |
| every other file | untouched | read and written as in [V0.1.5.2](V0.1.5.2.md) |

---

## 1. `keypadEnabled` — whether a tap on a numeric field opens the keypad

```json
{
  "consecutiveTransaction": 128,
  "motelName": "Motel Paraiso",
  "version": 3,
  "keypadEnabled": false
}
```

- **`true`** — tapping a price, quantity, duration or tower-number field opens the on-screen
  keypad (digits, clear, backspace), which types into the field.
- **`false`** — the fields behave as before: the physical keyboard (or the operating system's
  virtual keyboard) is the only way to enter a value.
- **Absent** — treated as `true`. A data directory written before this release therefore keeps
  the keypad, which is what a touchscreen installation without a keyboard needs; an
  installation that has a keyboard turns it off once from *Opciones programa* and the setting
  is written by that action.

The switch lives in the options hub (*Opciones programa → USAR TECLADO EN PANTALLA*). Toggling
it takes effect immediately — the keypad reads the setting when a field is tapped, so no restart
is needed — and it writes `applicationProperties` on the spot through
`MotelManagement.saveKeypadConfiguration()`, without touching the turn, the room files or the
inventory.

## 2. Unchanged

Every other key of `applicationProperties` (including `defaultTimeData` per tower, added by
[V0.1.5.2](V0.1.5.2.md)), `data/roomsInformation`, `data/turn`, `data/inventory`,
`data/emailConfig`, the completed turns in `history/`, the custom layouts in
`data/printTemplates/` and the `receiptPrints/` PDFs behave as documented for V0.1.5.2;
`"version": 3`, `ZonedDateTime` in `America/Bogota` and amounts as `long` in COP.
