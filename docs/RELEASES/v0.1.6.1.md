Numbering and state fixes: the numbers shown to the operator are the human ones everywhere, and deleting a tower, floor or room no longer leaves holes behind.

**Changes for this version**

- **Receipts**: a custom room receipt printed the raw zero-based grid indexes, so `roomNumber`, `floorNumber` and `towerNumber` came out as `0 / 0 / 0`. The template editor offers those fields and the preview already showed `3 / 1 / 2`; the printed receipt now matches the preview.
- **Room email**: the same leak in the `{towerNumber}` and `{floorNumber}` placeholders, which reported *Torre 0 / Piso 0* for the first tower and floor. Both carry the human numbers now.
- **Deleting closes the gap**: towers, floors and rooms are renumbered after a deletion, and their automatic names (`1-102`) follow. A name typed by the operator (`Suite`, `VIP`) is kept as it is. The *Número de la nueva torre* dialog, which asked for the internal value, is gone: adding a tower appends the next one.
- **Loading repairs old data**: a file saved by an earlier version after deleting a middle tower, floor or room used to crash the room grid (`IndexOutOfBoundsException`), because a stored floor number was used as a list index. The numbering is normalized on load now and the grid is indexed by position.
- **Reverting a configuration edit** restores the saved room states instead of bringing the rooms back all free.

**Data**: no file-format change — `data/applicationProperties` and `data/roomsInformation` stay at `"version": 3`. The only rule added is that a stored number equals its position; `docs/PERSISTENCE/V0.1.6.1.md` says what happens to a state file written by an older build after a deletion.

**Verified with** 641 tests.

**Requirements and how to run**

- **Java 25**
- The build is self-contained: every image, message bundle and factory template ships inside the jar
- The `.jar` of this family is published on [v0.1.6.2](https://github.com/TheAbsdag/Motel_management/releases/tag/v0.1.6.2); this exact version can be rebuilt from its tag with `.\mvnw.cmd clean package`. Run it with `java -jar Motel_management-0.1.6.1.jar`; the working directories (`data/`, `backup/`, `history/`, `receiptPrints/`, `logs/`) are created next to the jar on first run
- **Updating an existing installation**: copy its `data/` directory next to this jar as it is. There is no conversion step
