Two fixes that came up while preparing the inventory work: the room summary no longer jumps back to the top on every clock tick, and a turn can no longer be closed with no print option selected.

**Changes for this version**

- The room summary rebuilt itself on every 250 ms clock tick, so the grid jumped back to the top four times per second: floors below the fold could not be reached and a touch drag was interrupted. It now keeps one scroll pane and refreshes the labels in place, rebuilding only when a tower, floor or room is added or removed.
- The tower/floor grid no longer clips the 5th and later rooms of a floor, and no longer overflows the card with 3 towers: the rooms stretch with the window in a grid that keeps wide floors to two balanced rows. The screen is now a JFormDesigner form (title, time, date, scroll area, VOLVER and a legend with live counts of libres / limpieza / ocupadas / sobretiempo).
- IMPRIMIR PARCIAL and FIN TURNO stayed enabled after unchecking the last print option, so a turn could be closed with no option and the report was silently skipped. The buttons now follow the selection, in the turn manager and in the history detail, and the print option (1 = no print, 2 = summarized, 3 = detailed) is validated before touching the turn, the printer or the files.

**Data**: no schema change, the JSON stays at `version: 3`.

**Verified with** 597 tests; the jar builds and starts.

**Requirements and how to run**

- **Java 25**
- Only this `.jar` is needed: it is a self-contained build, every image, message bundle and factory template ships inside it
- `java -jar Motel_management-0.1.5.5.jar`. The working directories (`data/`, `backup/`, `history/`, `receiptPrints/`, `logs/`) are created next to the jar on first run
- **Updating an existing installation**: copy its `data/` directory next to this jar as it is. There is no conversion step

The inventory traceability work does not ship as a 0.1.5.x patch: it goes out as **0.1.6.0**.
