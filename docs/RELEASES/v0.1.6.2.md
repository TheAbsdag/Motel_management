Closing a turn now writes the closed turn to `data/turn`, so the turn that was just closed and reported is not resumed the next time the program is opened.

**Changes for this version**

- **FIN TURNO stores the turn on disk**: the controller ended the turn in memory and wrote `history/`, the XLSX report and the PDFs, but never rewrote `data/turn`. The file still said `"turnActive": true`, kept the content of the last transaction and had no `closingInventory`, so closing the program on the turn selection screen and opening it again resumed a turn that had already been closed and reported. The closed turn (with its closing stock snapshot) is written now in the same step that ends it.
- **A turn with no print option is not closed**: the print option is resolved before anything is ended, so an empty selection no longer closes the turn without a report. The button logic already made that state unreachable; the check now enforces it.

**Data**: no file-format change — `data/turn` keeps the same keys and stays at `"version": 4`.

**Verified with** 642 tests.

**Requirements and how to run**

- **Java 25**
- The build is self-contained: every image, message bundle and factory template ships inside the jar
- The `.jar` of this family is published on [v0.1.6.3](https://github.com/TheAbsdag/Motel_management/releases/tag/v0.1.6.3); this exact version can be rebuilt from its tag with `.\mvnw.cmd clean package`. Run it with `java -jar Motel_management-0.1.6.2.jar`; the working directories (`data/`, `backup/`, `history/`, `receiptPrints/`, `logs/`) are created next to the jar on first run
- **Updating an existing installation**: copy its `data/` directory next to this jar as it is. There is no conversion step
